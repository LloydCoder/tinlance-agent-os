# Agent Catalog v3 — Phase 33: 20K Canonical Expansion

Phase 33 establishes the strict release boundary for the strategic 20,000-canonical-archetype milestone.

## Non-inflation contract

The gate does not generate taxonomy entries. It accepts only an explicit canonical inventory whose entries already passed the governed candidate lifecycle. Provider, model, geography, deployment, tool, protocol, cost, latency, and authority are not semantic identity dimensions.

The existing Phase 26 controlled expansion remains bounded at its documented scale. Phase 33 does not multiply it synthetically to claim 20K coverage; additional entries must arrive through governed discovery, normalization, semantic review, provenance, and canonical publication.

## Fixed release invariants

- at least 20,000 canonical entries;
- every entry is CANONICAL;
- stable unique canonical identifiers;
- 100% provenance coverage;
- 100% review-evidence coverage;
- semantic uniqueness based on domain + capabilities + skills;
- at least 50 distinct domains;
- deterministic order-independent inventory digest;
- no execution or authority side effects.

## Architecture boundary

Catalog expansion remains descriptive. Platform owns authorization, admission, approvals, execution, budgets, sandboxing, evidence, audit, and delegation. Directory and Registry semantics remain separate.

## Gate

Phase 33 may merge only after exact-head CI is green. After merge, a forensic audit must validate the 20K contract and prior phase invariants before Phase 34 begins.
